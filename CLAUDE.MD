# TinyK - microKORG Synth Module for Ableton Move (Schwung Framework)

## Project Overview
- A 4-voice polyphonic / 2-voice dual-timbre virtual analog synth engine running on Ableton Move via the Schwung runtime.
- DSP core is C: `src/dsp/dsp.c` (engine), `src/dsp/dsp.h`, `src/dsp/syx_bank.h` (runtime .syx loader, included by dsp.c), `src/dsp/arp.c` / `arp.h` (arpeggiator; dsp.c includes arp.c once, so every build and tool still compiles dsp.c alone), `src/dsp/presets.h` (built-in bank, generated), `src/dsp/dwgs_waves.h` (the 64 DWGS waveforms, generated by `tools/trace_dwgs.py`). `src/dsp.c` / `src/dsp.h` are one-line include shims.
- UI: `src/ui.js` (the module's own screen), `src/canvas.js` (custom widgets for Schwung's param pages: the Arp Steps LEDs). Manifest: `src/module.json`. The engine also serves its own `ui_hierarchy` JSON (`MK_UI_HIERARCHY` in dsp.c): keep the two in step.

## Build, Install & Test
- `./scripts/build.sh` cross-compiles `build/dsp.so` (ARM64, Cortex-A72) and packages `dist/tinyk/` + `TinyK.tar.gz` (holding `tinyk/`). Toolchain order: Docker (scripts/Dockerfile, only if `docker` is on PATH) -> CMake when `$CROSS_PREFIX` is set -> `aarch64-linux-gnu-gcc` -> Zig. This Windows machine has neither Docker nor a GNU cross-gcc, so the build always takes the Zig path with the bundled `.toolchain/zig-windows-x86_64-0.13.0/zig.exe` (gitignored; a `zig` on PATH also works):
  `zig cc -target aarch64-linux-gnu.2.35 -mcpu=cortex_a72 -O3 -fPIC -shared -Wall -Wextra -Isrc -Isrc/dsp src/dsp/dsp.c -lm -o build/dsp.so`
  (glibc 2.35 target, matching the Move; the result must be warning-free). The host-side tools build the same sources natively with the same zig.exe (`zig cc` without `-target`), see Verification tools.
- Package contents: dsp.so, module.json, ui.js, canvas.js, presets.json, help.json, presets.h, release.json and an EMPTY `banks/` (README.txt only): a release never redistributes .syx banks, and `./scripts/install.sh` copies none unless `INSTALL_BANKS=1`.
- `./scripts/install.sh` copies the module to the Move over SSH: default `ableton@move.local` (key-based login), override with `MOVE_HOST=ableton@<ip>`. Destination `/data/UserData/schwung/modules/sound_generators/tinyk`; an old upper-case `TinyK/` there is migrated (its banks copied over, then removed); dsp.so is swapped via `dsp.so.new`; banks already on the Move are kept, and local `banks/*.syx` are copied only with `INSTALL_BANKS=1` (never TinyK_Default.syx, the built-in bank's source). Reload the slot (or restart Schwung) afterwards.
- Module id `tinyk` = directory name, lowercase: Schwung requires `^[a-z0-9][a-z0-9-]*$`, the shadow UI lowercases ids into the Set's slot files, and the chain host loads `sound_generators/<id>/dsp.so` from them on boot (ext4, case-sensitive). The old id "TinyK" saved slots as "tinyk" that never restored. Display name stays "TinyK".
- Slot persistence: Schwung autosaves `get_param("state")` into `set_state/<set>/slot_N.json` every ~5 s and hands it back via `set_param("state")` on boot / Set change (the C chain parser reads `synth.config.state`). A failed read (TinyK used to return -1 for "state") makes it keep the stale file forever. TinyK's state (`build_state_json` / `apply_state`): `tinyk_state` version, bank by name, preset, params, both timbres' params and extras, voice mode, timbre edit/balance, octave, delay time base.
- Release: bump `version` in `src/module.json` and `release.json` together. `release.json` stays 0.9.0 until the user launches (their call; module.json says 1.0.0). `release.json` (repo root, Schwung catalog format `{version, download_url}`) points at the GitHub release asset `https://github.com/fleshinachair/TinyK/releases/download/v<version>/TinyK.tar.gz`; the catalog entry needs `github_repo` fleshinachair/TinyK and `asset_name` TinyK.tar.gz.
- Shell scripts must stay LF and executable (`.gitattributes`, git mode 100755).
- Default bank: `python tools/make_default_bank.py` reads banks/MicroKorgFactory.syx and writes banks/TinyK_Default.syx: 128 original names (`NAMES`, 12 characters max) and a seeded jitter of 1-2 steps on 1-3 continuous values per active timbre (cutoff, EG attack / decay / release, Osc 2 tune; EG 0 / top, unison tune, selectors and vocoder programs untouched). It is a derivative of Korg's factory programs, not an original sound set.
- Preset generator: `python tools/extracts_presets.py [banks/TinyK_Default.syx]` writes presets.h (4 copies) and presets.json (2 copies). The committed presets.h comes from TinyK_Default.syx and is the compiled-in default bank ("Built-in"); the .syx files are gitignored and never shipped. `FACTORY_LABELS` is only the fallback for dumps without names.

## Architecture Rules & Guidelines
1. **SysEx Parsing:**
   - Always open and write files using explicit UTF-8 (`encoding="utf-8"`) to prevent Windows `cp1252` encoding errors.
   - Values extracted into `presets.json` and `presets.h` must normalize strictly between `0.0f` and `1.0f`.
   - Never overwrite valid patch data with placeholder or copy-pasted floats.
   - `tools/extracts_presets.py` and `src/dsp/syx_bank.h` are the same decoder in two languages: change both together and run `tools/test_bank_loader.py`.

2. **DSP & Voice Architecture:**
   - Cutoff, key tracking, filter EG and virtual patches are summed in control pitch (octaves), converted to Hz once: `fc = cutoff_base_hz * 2^(knob * cutoff_octaves + keytrack + EG + patches)`.
   - Filter Envelope Intensity (`env_int`) is bipolar (`0.5` = neutral, `<0.5` = negative modulation, `>0.5` = positive modulation).
   - In Layer mode (`voice_mode == 1`) each timbre has two voices (Timbre 1: voices 0 and 2, Timbre 2: 1 and 3), mixed by `timbre_balance`; Single mode gives Timbre 1 all four.
   - Voice assign (timbre byte +1 bits 6-7: 0 Mono, 1 Poly, 2 Unison; bit 3 trigger mode, 1 = multi) and unison detune (+2, cents) are decoded (`assign`, `unison_detune`, `trigger_multi`). Poly allocates per voice as before. Mono plays one voice, Unison stacks all the timbre's voices (2 in Layer, 4 in Single) on one note: detuned evenly over the unison detune (`unison_cents_scale` 1.0 cent per step: A.11's 10 gives a 12.0-cent split of the 2nd harmonic, the VST 12.4) and spread left to right (`unison_spread` 0.70: dry A.11 L/R correlation 0.45 vs the VST's 0.46, side/mid -4.2 dB both), each at 1/sqrt(n). Both keep a last-note key stack: releasing the sounding key goes back to the one still held; with single trigger a key pressed while another is held glides there without restarting the EGs.
   - Timbre pan (+26, `pan`) places each timbre's voices (constant power, unity at the centre), in both modes; the old fixed Layer pan (Timbre 1 at -0.3, Timbre 2 at +0.3) is gone. A voice starting from silence gets random oscillator start phases (xorshift seeded in synth_init, so renders still repeat). The chorus line is written every sample, so turning the chorus up never replays stale audio.
   - The voice mix is soft-clipped (`tanh`) so stacked voices / both timbres cannot clip digitally.
   - De-click: a voice starting from silence fades in over `DECLICK_SAMPLES` 44 (1 ms raised cosine, zero slope at the start) on top of its amp EG; the EG's fastest attack (1.5 ms RC) starts at its steepest slope and random start phases rarely start at zero, and the brightness tilt lifted that corner into a 12-20 kHz click (sine, attack 0: onset 12-20 kHz content -37..-44 dB re the note before, -56..-67 now). A sounding voice that is stolen or retriggered keeps its filter state and EG levels (they used to be crushed to 5 %, a step on an open filter: -22 dB before, -50..-74 now) and its velocity gain glides (`VEL_GLIDE_S` 0.5 ms) instead of stepping. All notes off (CC 120 / 123, voice mode change, state restore) fades sounding voices over `KILL_RELEASE_S` 3 ms instead of cutting them. A program change (`load_preset_from` -> `flush_for_program`) does the same, so a key held across a change of voice assign (Poly -> Mono / Unison: its note-off never matched the voice and the note hung until CC 123) cannot stick; the arpeggiator and held keys are dropped too, and the effect memories (Mod FX line, phaser, delay line and its feedback filter, DC blockers) are cleared at once when the output is silent, else the output ducks over `FLUSH_FADE_S` 6 ms, they are cleared at silence and it comes back (click-free; `test_program_change_flush`). Calibration unchanged (110.68).
   - Output headroom: the last stage of `render_segment`, after the Mod FX, delay, DC blockers, master volume and the soft-knee limiter, multiplies by `TINYK_OUTPUT_HEADROOM` (now 0.56, see the 2026-10-11 entry below; it was 0.45 on the old engine), so native Move tracks (staged around -12..-8 dBFS) are not overpowered while every drive / saturation curve stays as calibrated. The calibration library (`calibrate_dsp.build_library`, hence calibrate_dsp, test_bank_loader, render_demo_sweeps, fit_filter_sweep) is built with `-DTINYK_OUTPUT_HEADROOM=1.0f` to keep comparing against the VST takes at unity; `test_behavior.c` and `audit_all_presets.py` build the shipped scale (the audit's level thresholds move by -6.9 dB; `test_headroom` checks the peak bound).
   - Two DC blockers (~3.5 Hz): on the voice mix, and on the output after Mod FX and delay (B.35 SlowBend's subsonic bend, lifted by the Phaser's feedback, reached the output as a 0.07 offset).
   - Real-time path: no heap allocation, no file I/O. Renders must be deterministic (the noise generator is reseeded in `synth_init`).
   - Instances: every slot running TinyK is its own `v2_create_instance` (a calloc'd `tinyk_instance_t`: the `synth_engine_t` first, then that slot's get_param JSON scratch; freed by destroy_instance). Everything an instance plays or shows lives in its `synth_engine_t` (including `bank_file`, `noise_state`, `labels_reported`); `load_preset(synth, idx)` loads into the instance it is given. Shared between slots, read-only: the decoded .syx banks (scanned at the first create), FACTORY_PRESETS, tinyk_tuning, the host API / move-info. Never add mutable file-scope or function-static state; `g_synth` exists only for the legacy raw entry points and a NULL instance. test_bank_loader.py checks two instances side by side (`tinyk_v2_*_n`).

3. **Filter (svf_process_2pole):**
   - Zero-delay-feedback (TPT) SVF with the correct solution `hp = (x - (k + g) * s1 - s2) / (1 + g (g + k))`. The old `k * s1` (missing g) plus tanh on s1/u and +-2 state clamps went unstable near the cutoff ceiling and sprayed kHz of hiss (a 131 Hz saw through LPF12 res 0.35 at 12.9 kHz had an 8 kHz centroid). The loop is linear (stable for any k > 0); the filter input has a soft clip (`tanh`, gain 1 + 0.5 res) and nothing else; states have a wide safety clamp (`SVF_STATE_LIMIT` 64).
   - BPF12 is the SVF's band output; Q = 1/k exactly (checked numerically). Its centre has its own knob curve, `bpf_cutoff_octaves` 10.36 and `bpf_cutoff_offset` +0.56 octave (+0.50 / +0.43 / +0.37 octave over the LPF mapping at cutoff 32 / 64 / 96), and `bpf_k0` 2.13 (Q 2.12 at res 63): fitted on the VST takes `ref_bpf12_res63_cut{32,64,96}_c3.wav` (saw, Osc 2 / drive / EG int / key track off), harmonic rms 5.61 -> 3.37 dB. Only res 63 was measured: Q at other resonances scales with bpf_k0 (res 0 now 0.47).
   - Distortion (`drive`, timbre byte 27 = 0.5 when on) is in the amp section, after the filter: `dist_ceiling * tanh((1 + drive * drive_gain) * x / dist_ceiling)`, drive_gain 2.0, dist_ceiling 2.0. On the VST it is mostly level (+19 dB on B.11, spectrum nearly unchanged); the engine runs ~17 dB hotter relative to its clip points, so it gets +4.8 dB with B.11's shape intact (2.6 vs 2.5 dB rms clean). More gain buys level with buzz.
   - Damping: LPF24 stages start Butterworth (k0 = sqrt 2, measured on the VST), LPF12/HPF k0 = 2, both `k = k0 * (1 - 0.5 * res_damping_range * res)`. BPF: `k = bpf_k0 * 2^(-4.38 res)` (exponent from the earlier res 0 / 63 measurement; bpf_k0 fitted at res 63).
   - Cutoff ceiling `cutoff_ceil_hz` = 19 kHz; the SVF clamps fc to 0.45 fs internally.
   - Key tracking (superseded: see FILTER, SECOND PASS under SysEx Format Notes for the measured law): `(note - KEYTRACK_PIVOT) * (2 * keytrack - 1) * KEYTRACK_SLOPE / 12` octaves (keytrack 0..1, 0.5 = off), pivot 60, slope 1.0. (The VST measured ~2.0 about ~62 at +63, but that made the +48 presets worse; kept 1:1 until intermediate values are measured.)

4. **Brightness tilt:** (superseded for the noise: it now takes the tilt's whole inverse and a low-pass of its own, see NOISE below; `noise_tilt_db` is unused) the audible noise (noise level and Osc 1 Noise) was pre-shaped by the inverse of a lower shelf, `noise_tilt_db` 18 dB (same corner), so it kept part of the tilt's top. HPF12 has its own cutoff ceiling, `hpf_ceil_hz` 15 kHz (knob plus modulation; LPF / BPF keep `cutoff_ceil_hz` 19 kHz). Both were fitted together on A.21's off-beat hat (`ref_a21_timbre2_drum_c3.wav`, where LFO2 -> cutoff pins the HPF at its ceiling): at the shared 19 kHz ceiling nearly all the hat sat at 15-20 kHz (5-15 kHz content 34.4 dB under the kick vs 26.6 on the VST), so it read as quiet although its RMS matched; now 23.5 dB, the band profile within 3.1 dB rms (13.7 before), the hat 9.0 dB under the kick (VST 8.7). The calibration total moved 111.75 -> 111.84 (A28, the noise patch, 13.62 -> 13.71). S&H keeps the raw noise. The tilt itself is a first-order high shelf on the voice mix, after the filters and before the soft clip (`tilt_db` 26.7 dB, `tilt_hz` 20 kHz): ~+2 dB at 3 kHz, +7 at 8 kHz, +18 at 17 kHz. It matches the VST's open saw (co_127) within 1.6 dB rms. Post-filter is deliberate: it is linear there and leaves the pre-filter drive alone; a per-voice pre-filter tilt scored worse (106.8 vs 104.1).

5. **Virtual patch & LFOs:** per timbre, 2 LFOs (LFO1 saw/square/triangle/S&H, LFO2 saw/square/sine/S&H; tempo sync at the session tempo (`host_tempo_bpm()`: the Set tempo from Schwung's public move-info (`schwung_move_info()`, found by dlsym at init, audio-thread safe; `move_info_t` in dsp.h mirrors src/host/move_info.h, offsets checked by _Static_assert), unless Move follows external MIDI clock or move-info is invalid; then `get_bpm`, else `lfo_tempo_bpm` 120. move-info's tempo follows the tempo knob while stopped (polled on the Move 2026-10-07: 103 -> 120 BPM with the transport stopped); get_bpm is the measured MIDI clock while PLAY runs and only holds the last measured tempo when stopped. Smoothed: the Set tempo over ~50 ms, a get_bpm within ~50 ms for changes > 2 BPM and over ~1 s for the +-0.3 BPM clock jitter), and while the transport runs (`get_beat_position` >= 0) free-running synced LFOs lock their phase to the beat (cycle start on beat 0; not an LFO2 whose rate a patch modulates); key sync restarts at the positive peak; the saw FALLS +1 -> -1: 37 of 39 saw -> amp routes in the factory / MS2000 banks are positive, rhythmic gates like A.21 AutoHouse that a rising saw played backwards) and 4 patch slots (sources 0-7: EG1 (filter), EG2 (amp), LFO1, LFO2, velocity, keyboard, Pitch Bend (-1..+1), Mod Wheel (CC1, 0..+1; CC2 drives nothing); destinations pitch, osc2 pitch, osc1 ctrl1, noise, cutoff, amp, pan, LFO2 rate). Depth = full scale * (|int|/63)^`patch_int_curve` (2.4 measured); full scale 24 semitones (pitch, measured) and 10.61 octaves (cutoff, lower bound). Amp routes are not summed: each is a gain stage `max(0, 1 + amt * src)`, the product is squared and capped at full level (1 / timbre level), fitted on the A.21 hat (3.9 dB rms over its envelope vs 11.5 for the sum, which went silent at 2/3 of the cycle; silence exactly at the cycle end and a level kick half, as on the VST). Pan has its own `patch_pan_curve` 0.6 (chosen, not measured: +-7.6 dB swing at +20, hard L/R at +63; 2.4 gave +-0.7 dB). Bend and wheel sources are 0 until a message arrives, so a wheel at rest adds nothing. Patch LFO outputs are slew-limited (`LFO_SLEW_S` 1.5 ms per full swing) then one-pole smoothed (`LFO_SMOOTH_S` 0.5 ms): saw wraps, square edges, S&H steps and key-sync restarts no longer click (A.21's gate, A.31's S&H -> pan +63, checked in test_behavior).

6. **Arpeggiator (`src/dsp/arp.c`):** each program's own (program bytes 14-15, 32-36, see SysEx notes), decoded into `struct ArpParams` (`ARP_FIELDS`), loaded with the program (on/off as stored; the Arp knob `arp_on` on Perf overrides it until the next program; the Arp Settings and Arp Steps pages edit the rest and the step pattern; all are saved in the slot state). MIDI keys go through it (`key_note_on` / `key_note_off`); `synth_note_on` / `synth_note_off` stay direct, so single-note renders, calibration and the audit are unaffected. Types UP, DOWN, ALT1 (ends once), ALT2 (ends twice), RANDOM (deterministic xorshift), TRIGGER (all held keys together, the octave rising per step); range 1-4 octaves; resolution 1/24 .. 1/4; gate x step (100 % = to the next step, minimum 2 %); swing moves every second step by swing/3 of a step; the trigger pattern rests steps whose bit is SET (inferred: 17 of the factory's 23 arp programs store 0); the note order advances on played steps only; latch keeps the keys until the next key after a release. Clock: the transport's beat grid while it runs and key sync is off, else free-running from the first key at the session tempo; `synth_render` renders in segments ending at arp events, so steps start on the sample (one segment per block when the arp is off). Layer mode: the arp plays its target timbre (both, T1 or T2) and the other timbre plays the keys (A.21: T1 bass arpeggiated, T2 drum held). Arp notes restart the target timbre's key-synced LFOs. The program's own arp tempo (bytes 30-31) is ignored for the session tempo. Checked in test_behavior (`test_arp`) and test_bank_loader.

## Presets, banks and selection
- Built-in bank: `FACTORY_PRESETS` in presets.h (used when there are no banks).
- Runtime banks (`syx_bank.h`): `v2_create_instance` scans `<module_dir>/banks/*.syx` once, decodes up to 16 banks (alphabetical, case-insensitive) into static storage (~54 KB each). Accepted: microKORG `F0 42 3g 58` or microKORG S `F0 42 3g 00 01 40`, function `4C` (ALL PROGRAM DATA, 128 programs, 37163 bytes) or `50` (ALL DATA). Anything else (single-program `40` dumps, truncated/oversized/random files) is skipped; with several SysEx messages in a file the first valid bank is used. Selecting a bank later is a pointer swap (`active_presets()`), never file I/O.
- Program list (`rebuild_playlist`, per instance, rebuilt on a bank change): TinyK has no vocoder input, so a program whose own voice mode byte (byte 16 bits 4-5) is 3 is left out, wherever it sits (`Preset.voice_mode` 2 in presets.h and syx_bank.h; the JSON `voice_mode` stays 0/1 and `data_valid` false). Every bank keeps the hardware matrix: Category = matrix row (`cat_row`, named Trance ... SE/Hit, row 8 "Other"), Program = the row's playable programs in matrix order, A side then B side (`cat_slot[category][position]`, `cat_n`, `slot_cat`, `slot_pos`), each keeping its own A.11-B.88 label and coordinate (the served `short_options` are the real A1..B8 codes, so a skipped slot leaves a gap). A row without a playable program is not offered, so `category_count` is 7 for the factory banks and TinyK_Default.syx (112 programs), 8 when row 8 holds ordinary programs (the real MS2000 banks: 107-128 programs). `genre_category` is the category index, `program_num` the position + 1, `patch_count` the current category's size (all clamp to what exists). The jog wheel (`preset`, `preset_count`, `preset_name:<i>`) counts the playable programs in matrix order (ordinals, `play_map` / `play_ord`); `current_preset` and the state's `preset` stay bank slots (an old state on a vocoder slot loads the nearest playable one, `playable_raw`; `load_preset` never loads a vocoder program). The legacy matrix keys (`program` 11..88, `bank_side`) address slots and snap to the next playable one. A bank of nothing but vocoder programs keeps all 128. `category_count` / `category_names` / `patch_count` serve src/ui.js. Checked in test_bank_loader.py (`vocoder_banks`: moved, removed, half-row and whole-row vocoder flags) and by sweeping every bank in banks/.
- Labels: the stored 12-character name when present ("A.11 Trancey" style names keep their code; plain names get it prepended), else the code ("A.11").

## Controls & UI (Schwung host)
- The host builds the screens from `ui_hierarchy` (src/module.json, also served by the engine as MK_UI_HIERARCHY, generated from it and checked identical by test_bank_loader.py) plus the engine's live `get_param("chain_params")`, which overrides inline metadata. Enums display their option names and travel as indices; set_param also accepts option names. Host code for reference: shadow/ and shared/param_pages/ under /data/UserData/schwung on the Move.
- PAGE LAYOUT, 2026-10-09 (Josh: "filter envelope and controls should be on a single page"; this supersedes the knob lists in the next entry, whose notes on the root browser, labels, Category / Program and the Arp pages still hold). One page per section of the instrument, each with its own envelope: **Perf** `perf` (Category, Program, Arp, Mode, Layer, Voice, Portamento, Layer Bal), **Osc** `osc` (Wave 1, Control 1, Control 2, Wave 2, Sync/Ring, Semi, Tune, Osc Mix), **Filter** `filter` (Type, Cutoff, Resonance, EG Int, Filter A/D/S/R), **Amp** `amp` (Noise, Level, Distortion, Pan, Amp A/D/S/R), **Mod** `mod` (LFO1 Rate, LFO2 Rate, Mod Wheel, Filter Key Track: four knobs), **Effects** `fx` (Mod FX Type / Speed / Depth, Delay Type / Time / Feedback / Mix, Master Vol), then Arp Settings, Arp Steps, Bank. The `env` and `mix` levels are gone. New page params: `osc1_ctrl1` / `osc1_ctrl2` (int 0..127, the edited layer's `timbre_extra.osc1_ctrl`; Control 1 also writes `pulse_width`, which is no longer on a page), `modfx_type` / `delay_type` (enums) and `modfx_speed`; `modfx_type` and `modfx_speed` are now in the slot state (they were not saved). `drive` is an Off / On selector ("Distortion": any stored value above 0 is on). `chorus_mix` is labelled Mod FX Depth. DWGS: the manifest's Osc level lists `osc1_ctrl1` and `dwgs_wave`; the engine SERVES one of the two (`json_cut_object`), so the page never shows both (it showed Pulse Width, DWGS Wave and the list at once before). The separate **DWGS Waves** list level is REMOVED (Josh: "why is dwgs picker its own page when it's on a knob?": the host lists every level as a page); the `dwgs_pick` / `dwgs_list` engine params remain. test_bank_loader compares the served hierarchy with the manifest minus that cut. ui.js `PAGES`, help.json and docs/USER_GUIDE.md follow the same order (the guide's page sections are generated in the same shape: 9 pages).
- Root level: only the preset browser (`list_param` preset, `count_param` preset_count, `name_param` preset_name; no knobs): the header shows the live patch name and the jog wheel steps all 128 programs. Its nav entries are the knob pages in this order: Perf, Osc, Envelopes, Mix/Filter, Effects, Arp Settings, Arp Steps, Bank (the sound-design pages together, then the arpeggiator, the bank selector last; src/help.json's Pages follow the same order, checked by test_bank_loader), each its own level (the host names a page after its level and re-anchors a renamed page by level): **Perf** (`perf`, "Option B": Category `CAT`, Program `PROG`, Arp, Mode (`voice_mode`, Single / Layer), Cutoff, Resonance, Amp Rel, Layer (`timbre_edit`, L1 / L2): Mode and Layer sit next to the per-layer macros they switch; Amp Atk moved to Mix/Filter's 8th knob), **Osc** (`osc`: Wave 1, Wave 2, Pulse Width, Semi, Tune, Voice (`voice_assign`: Mono / Poly / Unison, per layer), Layer Bal (`timbre_balance`), Mod Wheel; while the edited layer's Wave 1 is DWGS the third knob is `dwgs_wave` instead of `pulse_width`, see DWGS picker below), **Envelopes** (`env`: Filter Atk/Dcy/Sus/Rel, Amp Dcy/Sus, Key Track, EG Int), **Mix/Filter** (`mix`: Osc Mix, Noise, Sync/Ring, Filter Type, Drive, Level, Portamento, Amp Atk), **Effects** (`fx`: Chorus Mix, Delay Time/Fdbk/Mix, Master Vol, Pan, LFO1/LFO2 Rate), **Arp Settings** (`arpset`: `arp_type` UP/DOWN/ALT1/ALT2/RANDOM/TRIGGER, `arp_range` 1-4 Oct, `arp_resolution` 1/24..1/4, `arp_gate` 0..100 %, `arp_swing` -100..100 %, `arp_latch`, `arp_key_sync`, `arp_target` Both/Timbre 1/Timbre 2; one table, `ARP_PARAMS` in dsp.c, serves set/get, chain_params and the slot state; a turn changes the running arpeggio at once: resolution / swing re-find the next step, latch off drops keys no longer held, a target change moves the arp and the held keys to their new timbres), then **Arp Steps** (`steps`: `arp_step1`..`arp_step8`, enum Rest / Play = the program's trigger pattern, live; a step past the pattern's length extends it; pattern and length are saved in the slot state). The Arp Steps cells draw as the microKORG's 2 x 4 step LEDs: each step param declares `viz: {kind: "custom:tinyk_step", extra_keys: ["arp_playhead"]}` (served in chain_params and inline in module.json), and the host loads `src/canvas.js` (`globalThis.canvas_overlay.widgetKinds`) for any module whose chain_params declare a `custom:` kind; each cell's 32 x 15 picture sits above its label: hollow box = Rest, filled = Play, dotted = past the pattern length, inverted (a lit block with the box cut out) = the sounding step. A custom group cannot span the two rows, so it is one widget per cell. The host reads one param per tick (~42/s) in rotation, so `arp_playhead` (read-only, `format_arp_playhead`: `0,<len>` stopped, `1,<len>,<next step mod 1680>,<ms to it>,<step ms>,<swing>` running) refreshes about every 240 ms on that page; the widget runs the playhead on by itself between reads (swing-aware, ignores a one-step-back reading within 60 ms of a boundary, hides it after 1.5 s without a fresh reading). Draw hooks get cached values only (a read costs ~2.8 ms against a 1.68 ms page render). An `as_page` canvas param would add a separate page next to the knob grid instead. Category = `category`, enum of 7 in a factory-layout bank (Trance, Techno/House, Electronica, DnB/Breaks, Hiphop/Vintage, Retro, SE/Hit = matrix rows 1-7; see Program list below); Program = `patch`, 16 positions A1..A8, B1..B8 = both bank sides of that row. Slot = (patch / 8) * 64 + category * 8 + patch % 8 (`program_raw`). There is no standalone A/B knob: Program 1-16 covers both sides. Not on any page: detune (replaced by Semi/Tune), sub_level (the microKORG has none), mod_int, vel_sens.
- Live labels (chain_params and the served ui_hierarchy follow the engine state): Program's options are the category's patch names in the active bank ("B.12 ARPEJMATR", shown on touch/turn) with `short_options` A1..B8 for the cell square (module.json keeps the static A1..B8). Terminology: the two sounds of Layer mode are **layers** (L1 / L2; "Timbre" survives only in internal names and keys such as `timbre_edit`, `timbre_balance`), and **voice** means polyphony only (Mono / Poly / Unison, `voice_assign`; the internal key `voice_mode` is shown as "Mode"). The sound-design pages (Osc, Envelopes, Mix/Filter) are named "... [L1]" in module.json (Perf carries no badge); the engine serves "[L2]" while Layer 2 is edited (Layer mode + Layer 2, `edit_timbre()`). In Layer mode the per-layer controls (including Perf's Cutoff / Resonance / Amp Rel) get `label` "L1 <label>" / "L2 <label>" and `short_name` "L1.CUT" / "L2.CUT" etc. (`T2_LABELS`, the digit swapped for Layer 1); Single mode keeps the plain labels and serves Layer's options as "N/A (Single)" twice (short "N/A": two options, so the stored choice stays a valid index for Layer). `timbre_badge()` is 0 Single / 1 / 2. The host re-reads both on a preset jog or list pick but not on a knob turn, so after a Category/Bank/Layer/Mode change (or a Program in the other voice mode) `is_loading` answers "1" once (`synth->labels_reported`, per instance) and the host re-reads on its 1 -> 0 edge.
- Host-facing value formats: selector params (`SELECTORS` in dsp.c: wave1, wave2, sync_ring, filter_type, voice_assign) are enums over the 0..1 engine value, with `short_options` for the option square (<= 4-5 narrow characters fit one line; longer folds, "Single" -> SIN/GLE, so Voice Mode / Timbre Edit carry SNGL/LAYR, T1/T2). Filter Type: LPF24, LPF12, BPF12, HPF12. Sync / Ring is in the hardware order Off, Ring, Sync, Ring Sync (OFF, RING, SYNC, R.SNC), remapped to the engine's off, sync, ring, both (`SYNC_RING_TO_ENGINE`, as in syx_bank.h). wave1/wave2 are enums (Saw, Square, Triangle, Sine, Vox, DWGS, Noise / Saw, Square, Triangle; short SAW, SQR, ...), so the host draws its waveform icon (Vox and DWGS fall back to its sine). They travel as indices; set_param also takes names, and a value with a decimal point as the normalized 0..1. `osc2_semi` (-24..24) and `osc2_tune` (-50..50 cents) are ints that read and write `detune` (clamped to its +-24 st). `level` and `noise_level` are the edited timbre's `timbre_extra` level / noise level. `mod_wheel` (int 0..127, cell "MOD") stands in for the wheel the Move lacks: it sets the Mod Wheel patch source (`modwheel_src`) like CC1 does, last mover wins, and reads back CC1 too. The program EQ plays but has no page (see SysEx Format Notes).
- DWGS picker: `dwgs_wave` (per layer, enum of 64: options "42 Organ3" for the overlay, `short_options` the hardware's wave numbers "42", which stay whole in the cell's option square; names of 6+ characters would fold to two lines of 3) reads and writes `timbre_extra.dwgs`, so the slot state already carries it. It shares the Osc page's third knob with Pulse Width, which does nothing for DWGS (the hardware's Control knobs change role with the wave the same way): the served `ui_hierarchy` swaps `pulse_width` for `dwgs_wave` in `osc.knobs` while `dwgs_knob_shown()`, and `label_context` includes that flag, so a Wave 1 turn pulses `is_loading` and the host re-plans the page (the knob list is rebuilt from the fresh hierarchy; module.json keeps `pulse_width` there and declares both params). The enum steps one option per 4 detents, 1 with Shift. The **DWGS Waves** page (`dwgs_list`, an items level reached by a door in `osc.params`, so it sits right after Osc; `items_param` dwgs_list = `[{"index","label"}]`, `navigate_to` osc) lists all 64 by number and name. Its `select_param` is `dwgs_pick`, NOT `dwgs_wave`: the host strips every level's selector keys from all knob pages, so sharing the key would drop the knob and shift the others left. `dwgs_pick` selects the wave and also turns Wave 1 to DWGS; its getter answers the index (the host marks the current row by `parseInt`, with no pre-scroll). The same stripping applies to `bank_file`, the Banks list's `select_param`: in the host source read for this (schwung-current) the Bank knob page is not planned at all, only the Banks list; not checked on the device.
- Bank page (`bank` level, entered from the root's "Bank" entry): the **Bank** knob (`bank_file`) whose enum options are "Built-in" plus the .syx file names found at start-up (from the live chain_params, JSON-escaped); `bank_file_name` returns the active name, `bank_file_count` the number of choices. "Browse banks" opens `bank_list`, an items level (`items_param` bank_list returning `[{"index","label"}]`, `select_param` bank_file, back to root). Changing bank keeps the program.
- src/ui.js mirrors this for the module's own screen: PERF, OSC, ENVELOPES, EFFECTS, MIX / FILTER and BANK pages; Osc / Envelopes / Mix pages show [L1]/[L2] in the header and the per-layer controls L1.xxx / L2.xxx labels in Layer mode (flags `layerLabels`, `layerBadge`); Program shows the patch name.
- Navigation (Schwung host, shared/param_pages): a level's `{"level"}` entries are not clickable cells on a knob page, only edges of the page tree (a door on Perf to Arp Settings would just rename that page "Perf/Arp Settings"), so there is none; a module cannot switch the host's page (the controller never opens a screen on a module's request). Shift+Click opens the section picker anywhere (jog, click to jump); Shift+jog pages by section. A level's params may hold nav entries `{"level", "label"}` (doors, like Bank's "Browse banks") or a `menu`; an items level may `navigate_to` a level after a pick.
- Legacy keys still accepted: `bank_side`, `program` (11..88), `genre_category`, `program_num` (1..16), `preset` (0..127; integer strings are indices). Other getters: `bank_file_name:<n>`, `preset_name:<idx>`.

## SysEx Format Notes (verified)
- 128 programs x 254 bytes after 7-to-8 unpacking. Timbre 1 at byte 38, Timbre 2 at 146.
- Voice mode is byte 16 bits 4-5 (0 = Single, 2 = Layer, 3 = Vocoder). Byte 14 is NOT the voice mode.
- Timbre offsets: 1 voice assign (bits 6-7) / trigger mode (bit 3), 2 unison detune (cents), 26 pan, 7 osc1 wave, 8 / 9 osc1 Control 1 / 2 (`osc1_ctrl1` / `osc1_ctrl2`, raw / 127; `pulse_width` repeats Ctrl 1 for the Pulse wave; for Sine, cross-mod depth / LFO1 modulation of it), 12 osc2 wave/mod select, 13/14 osc2 semitone/tune, 16/17/18 osc1/osc2/noise level, 19 filter type, 20 cutoff, 21 resonance, 22 EG1 int, 24 key track, 25 amp level, 27 bit 0 distortion, 30-33 EG1 (filter) ADSR, 34-37 EG2 (amp) ADSR (checked: swapping or ADRS order scores far worse), 38-40 LFO1 (wave/key sync, rate, tempo sync), 41-43 LFO2, 44-51 four patches as (route: bits 0-3 source, 4-7 destination; intensity 64 = 0).
- Hardware backup dumps can have blank names (bytes 0-11); VST exports (e.g. banks/MicroKorgFactory.syx) carry real names. test_bank_loader.py blanks them for its scan / label checks.
- `wave1` is index/6 over Saw, Pulse, Tri, Sine, Vox, DWGS, Noise. Vox is an additive approximation, not the sampled wave.
- DWGS (timbre byte 10, `dwgs` = wave / 63): the 64 waveforms are Fourier series in `src/dsp/dwgs_waves.h`, digitised by `python tools/trace_dwgs.py <pdf>` from the scope plots in "Korg microKorg DWGS Waveform Reference List" (one capture per wave of the hardware's output at 220 Hz; the PDF is not in the repository, and the tool needs poppler's `pdftoppm` and Pillow). 96 harmonics per period of the note, tracing residual 0.5-6 mV rms of a 550 mV range; the waves keep their relative level (loudest peak 1.0). 58 waves repeat every period. SynSine3, Digi8 and Endless repeat every 2 periods and Digi2, Bell3 every 1.5 (stored as 3): they hold partials between the note's harmonics, and the table spans `periods` of the note (`voice_t.osc1_cycle` counts them). Bell4 does not repeat within the 10 ms shown: its partials (ESPRIT) are snapped to a 5-period table, an approximation of the snapshot rather than a recovered wave (residual 9 mV); Endless's detuned partial pairs are likewise only approximated (4 mV). The traces include the hardware's output stage (AC-coupling droop on flat tops). Engine: `dwgs_build_tables` builds 7 band-limited levels per wave (96, 48 ... 1 harmonics at 1024 ... 32 samples per period, ~600 KB static, shared read-only by all instances) at the first `synth_init`, about 50 ms on a desktop core and not yet timed on the Move; the oscillator reads the richest level under Nyquist with a 4-point Hermite interpolation (off-harmonic energy at C7 -44 dB or better; the PolyBLEP saw through the same chain: -19 dB). `python tools/test_dwgs.py` renders every wave against its stored series (all 64 follow one gain curve within 0.42 dB rms) and checks the picker.
- Arpeggiator (program bytes, checked against the factory banks; NOT timbre +41..45, which are LFO2 and the patches): 14 trigger length - 1, 15 trigger pattern (bit n = step n + 1, set = rest), 30-31 arp tempo, 32 bit 7 on / bit 6 latch / bits 4-5 target (both, T1, T2) / bit 0 key sync, 33 bits 0-3 type / bits 4-7 range - 1, 34 gate %, 35 resolution 0..5, 36 swing (signed %).
- Delay, measured on the VST (`tools/vst_ab.py delay`, noise bursts; engine and plug-in agree to 0.1 ms and 0.001 in gain on 13 settings; `tools/test_delay.py` holds the numbers): `delay_time_s` is the knob's own curve, a fraction of a 65536-sample line at 48 kHz (1.3653 s) in straight segments, 0.01 at 0, 0.16 at 64, 0.40 at 110, 0.60 at 120, 0.80 at 125, 1.0 at 126, 1.2 at 127 (13.7 ms, 218 ms at the centre, 1.64 s; all 128 values measured; it was linear 0..1 s before). `delay_gain`: the hardware's one Depth is a single gain g for the first repeat and for each further one (repeat n = dry * g^n), 0 .. 0.300 at depth 64 .. 0.990 at 127 in two straight lines, times 1 - (time / 1.3653 s) / 4 (the same factor at every depth). The repeats keep their spectrum, so the old feedback low-pass, tanh, 0.6 feedback cap and `delay_send_scale` are gone (the tuning field is unused), and the line is read at whole samples (interpolating between samples low-passed every repeat). Program byte 22 is the type (`Preset.delay_type` 0 / 0.5 / 1, `synth->delay_type`, engine param and slot state `delay_type`, no page): Stereo = each side repeats on its own side; Cross = each repeat swaps sides, the first one already; L/R = the sides are summed to mono ((L + R) / 2) and the repeats alternate left, right. The old right tap at 0.75 x the time is gone. The built-in bank plays Stereo for every program (presets.h has no type data, as with the EQ). The Effects page keeps separate Fdbk and D.Mix knobs: each runs through the same gain curve, and a program sets both from its Depth. Not measured: the tempo-synced case (assumed the same gain law at the synced time).
- Program byte 19 is the delay tempo sync: bit 7 on, bits 0-3 the time base, 1/32 .. 1/1 (`DELAY_SYNC_NOTES`, the reverse of the LFO note order: the factory's common 7 / 5 / 8 are then 3/16, 1/8, 1/4). Decoded as fx `delay_sync` ((index + 1) / 15, 0 = free) by both decoders; a synced program's Delay Time knob steps the time base at the session tempo (`delay_sync_note`). The delay buffer is 2 s; free delay times stay 0..1 s.
- Host API: Schwung's move-info (`schwung_move_info`, see Virtual patch & LFOs) is the live Set tempo; `host_api_v1_t` in dsp.h mirrors Schwung's src/host/plugin_api_v1.h field for field (get_bpm at +88, get_beat_position at +112, checked by _Static_assert); every callback is NULL-guarded. Never append fields to it.
- Mod FX: program byte 23 LFO speed (`modfx_speed`), 24 depth (`chorus_mix`, 0 = off), 25 type (`modfx_type`: 0 Chorus/Flanger, 1 Ensemble, 2 Phaser), decoded by both decoders (FX_FIELDS now 7). `modfx_process` in dsp.c: Chorus/Flanger is one tap per channel on a triangle LFO, L/R in anti-phase, delay `chorus_center_ms` 5 +- depth x `chorus_depth_ms` 3.7, a `chorus_wet` 1.0 copy added to the dry signal; rate = `modfx_rate_lo_hz` 0.05 x `modfx_rate_span` 600^speed (the LFO knob curve). ESTIMATED, not fitted, from `ref_a11_modfx_speed44/80.wav`: speed 44 shows a triangle delay sweep of about 2..8 ms (cepstral track, 10-90 % 2.8..7.7 ms), speed 80 a 5.7 Hz L/R swing absent from the dry and speed-44 takes (read as twice a 2.8 Hz LFO, the curve's value; the curve gives 0.46 Hz at 44), wet takes +3.9 / +1.6 dB over the dry one (TinyK +3.1), L/R correlation 0.17 / 0.11 (TinyK 0.19 / 0.22). A.11's own modulation (unison beating, LFO1 -> pan at 2.3 Hz) dominates every other feature, so these takes cannot pin the rate curve: a plain patch (one saw, Poly, no LFO / pan routes, filter open, 8-10 s notes) at several speeds and depths would. Ensemble (three sine taps 120 degrees apart, `ENS_*`) and Phaser (six all-pass stages, feedback, summed with dry at 0.707, `PHASER_*`) are chosen, not measured. `modfx_speed` / `modfx_type` are also engine params (not on a page yet).
- EQ: program bytes 26 Hi frequency (0..29 = 1.00..18.0 kHz), 27 Hi gain (64 +- 12 dB), 28 Low frequency (0..29 = 40..1000 Hz), 29 Low gain, per Korg's MIDI implementation (rev 1.4, tables T-10 / T-11), decoded by both decoders into `struct EqParams` (`Preset.eq`, EQ_FIELDS: index / 29 and 0.5 + dB / 24, 0.5 = flat). Engine: `eq_update` / `eq_band` in dsp.c, a Low and a Hi shelf on the stereo output after the delay and before the output DC blocker, per instance (`eq_freq`, `eq_gain`), saved in the slot state (`eq_low_freq` ... `eq_hi_gain`, also engine params; not on a page). The table frequencies are Korg's; the shelf shape is measured on the VST (`tools/vst_ab.py eq`): first-order shelves with the table frequency as the corner, 3 dB short of full gain, a cut mirroring the boost. Engine and VST agree within about 0.2 dB at every frequency sampled across nine settings (0.5-1.6 dB rms over 40 Hz - 18 kHz, most of it a ripple near 12 kHz in the plug-in's noise renders that is there with the EQ flat too; method noise 0.15-0.26); a second-order RBJ shelf, tried first, was 1.1-3.6 dB off. A band at 0 dB is skipped, so a flat EQ is bit-identical to none. The BUILT-IN bank is flat: presets.h was patched with `{ 0, 0.5, 0, 0.5 }` on every program because TinyK_Default.syx was not at hand; regenerating it with `tools/extracts_presets.py` fills in the real values. External patches in test_render.c take theirs from `tinyk_set_patch_eq` (a zero-filled struct would mean -12 dB), which `calibrate_dsp.Engine.render_patch` now always sends, so the mk_*.syx reference programs render WITH their EQ: re-run `calibrate_dsp.py baseline` (110.68 was measured without it). `python tools/test_eq.py` checks decoder parity on a bank it writes itself, the response against the design, the flat case and the slot state. In the KorgUSA bank 40 of 112 synth programs have a non-zero gain.
- Measured on the VST and applied 2026-10-09 (Josh's direction: a faithful model wherever it matters sonically, no major UI rework): (1) VELOCITY does not set the level or the filter EG depth: the plug-in has no velocity sensitivity (the same level at every velocity) and velocity acts only through a virtual patch; `vel_gain` is 1 and `vel_sens` defaults to 0 (tools that play velocity 100 are 2.1 dB louder than before). (2) PAN is a linear balance, L = 1 - place, R = 1 + place (unity at the centre, the near side +6 dB at a hard pan; it was constant power), and the position moves at most `PAN_SLEW_PER_S` (left to right in 2 ms, the plug-in's 10-90 % of 1.61 ms under a square LFO). (3) PATCH -> PAN adds source * (1.183 u + 0.801 u^2), u = |int| / 63, to that position (Velocity -> Pan at six intensities; +63 is hard over at half the source); `patch_pan_curve` is unused. (4) UNISON: four voices at -d, -d/2, +d/2, +d cents for a detune of d, each at a full voice's level (the stack is +6 dB over one voice; it was 1 / sqrt(n)), all in the centre; `unison_spread` and `unison_cents_scale` are unused. Two voices (Layer mode) are assumed -d, +d, not measured. `test_lfo_steps_click_free` now bounds the S&H -> pan +63 burst by the plug-in's own figure (-9.1 dB by that measure; a side falls silent between steps under the measured depth, so 'within 5 dB of unmodulated' no longer means anything).
- Osc 1 Sine CROSS MODULATION (Control 1 / 2), measured on the VST and applied: Osc 2's waveform modulates the sine's frequency linearly and through zero by `XMOD_MAX_HZ` 24 kHz * depth^2 in Hz whatever the note (95 Hz at Control 1 = 8 on 110, 220, 440 and 880 Hz carriers; sidebands against a modulator a fifth up fit to 0.1-0.5 dB for Saw, Square and Triangle), depth = Control 1 + Control 2 * LFO1 + patches -> Ctrl 1, Osc 2's level irrelevant. Patch -> Ctrl 1 adds source * (0.596 u + 0.404 u^2) of the whole knob. This replaces the fitted pitch law for A.21's synced kick (`sine_xmod_*`, removed; `xmod_semitones` / `xmod_offset_semitones` unused): with Osc 2 synced the same FM gives a pitch shift, but the A.21 takes were NOT re-checked (not in this checkout). In the bank A/B the Sine-with-controls programs went from 18-21 dB tone error to 11-12.
- FILTER, measured on the VST and rebuilt (`tools/vst_ab.py filter`; the full description is the comment above `svf_core` in dsp.c): the plug-in's filter is a Chamberlin state-variable filter run once per sample (`lp += F bp; hp = x - lp - q bp; bp += F hp`), linear, and that recurrence reproduces its 12HPF / 12BPF curves to 0.06-0.13 dB. F = Fc(cutoff) x a resonance ratio (x 1.72 at 60, x 2.0 at 127: resonance raises the corner an octave); the knob is 10.56 octaves from 32.7 Hz, bent over as Fn / sqrt(1 + (Fn / 0.915)^2). q falls about as (1 - res / 127)^2 to 0.00026 at 127 (a 1 s ring; the top three points come from ring-down times). One output gain per resonance, the same for all types: flat to ~84, then falling as fast as the resonance rises, so the peak stops near +17 dB and the rest sinks (-40 dB at 127). 12BPF = x 1.32 bp; 12LPF = x 2.94 lp through the low-pass types' extra stage, 24LPF = lp x 2.19 through that stage at unity gain and a second identical core x a per-resonance gain (both superseded forms and the stage itself: see FILTER, SECOND PASS below). Engine against plug-in over 4 types x 6 cutoffs x 6 resonances: median 0.76 dB rms, mean 1.04 (12HPF and 12BPF 0.0-0.3 dB below cutoff 80); before, the resonant peak was 20-100 dB short and an octave low. The old TPT filter, its input tanh, `cutoff_base_hz` / `cutoff_octaves` / `bpf_*` / `res_damping_range` / `lp24_res_scale` / `hpf_ceil_hz` / `cutoff_ceil_hz` are no longer used by the filter (the tuning fields remain; `cutoff_base_hz` is still the unit the cutoff modulations are added in, and `env_octaves` / `patch_cutoff_octaves` / key tracking are unchanged and unmeasured against the new knob scale).
- ENVELOPES, measured on the VST and rebuilt (the comment above `EG_TIME_S`): every stage is a finite ramp, attack E = 1 - (1 - x)^2, decay E = S + (1 - S)(1 - x)^2, release E = L (1 - x)^2, x = time / T(knob), with ONE time table for all three stages (instant at 0, 0.79 s at 64, 1.6 s at 100, 30 s at 127; a decay or release has a floor of 8-31 ms below knob 8), and the amp follows E^2 (sustain 64 = 0.254 of full). Level contours of ten ADSR settings against the plug-in: 0.1-1 dB rms wherever the times are above ~20 ms. The filter EG and patch sources take E itself (assumed). `attack_scale` / `decay_scale` / `release_scale` still scale T.
- LFO RATES, measured on the VST (a triangle LFO -> pan, the level's period; `LFO_RATE_HZ`, every 8 knob steps): 0.016 Hz at 0, 0.25 at 24, 1.75 at 40, 5.0 at 64, then doubling every 12 steps (33 Hz at 96, 82 at 112). The old 0.05 x 600^knob was 4-5 x too slow from the middle up (1.3 Hz at 64, 6.3 at 96). The same table serves the per-timbre patch LFOs and the page's LFO 1 / 2 knobs.
- MOD FX, measured on the VST (white noise from the mixer and a sine through each type; the comments in `modfx_process`). Each type has its OWN rate curve. Chorus/Flanger (`MODFX_RATE_HZ`: 0.045 Hz at 0, 0.41 at 40, 2.4 at 64, 12 at 96): one moving tap per side, anti-phase triangle; depth moves the sweep down and narrows it (6.5-18.5 ms at 40, 2.4-9.0 at 100, 0.6-4.6 at 127), takes the mix from dry to an even blend by 40 and on to nearly all wet above 80, and above 40 feeds the tap back (0.90 at 127). Noise level and L/R correlation against the plug-in: within about 1 dB and 0.1 at depths 40-100, 2 dB low at 127. Phaser (0.00149 x speed^2 Hz): reproduced as its measured response, two notches at fc / 2.36 and fc x 2.36 (Q 0.37) around a peak at fc (+15 dB at depth 40, +31 at 127) over a floor of -1 .. -5 dB, fc sweeping 490 Hz - 3.1 kHz, mono; no all-pass chain with feedback fitted it (5-8 dB), this form fits a held sweep to 0.8-1.1 dB and the octave bands of a running one to ~2 dB except 250 Hz at full depth (the plug-in +3.6, here -6.8: its sweep shape is not a triangle in octaves, unresolved). Ensemble: only level and width are matched (an even dry / wet blend from depth 64, -3 dB, L/R correlation 0.98 at 32 falling to 0.62 at 127; here 0.98 .. 0.77); its taps (three near 8 ms, moving very little) are still chosen. The delay taps are read with a 4-point Hermite interpolation. With these and the LFO rates the bank A/B with FX on went from tone median 6.0 to 5.2.
- PATCH DEPTHS AND SOURCES, measured on the VST (the comment at `patch_amt` in dsp.c). The depth curve depends on the source's family as well as the destination. EG1 / EG2 / LFO1 / LFO2: pitch and osc 2 tune by a table (1 semitone at 16, 5 at 32, 12 at 48, 24 at 63), cutoff 7.83 octaves x u^2, amp u^2, pan 2 u^2. Velocity / keyboard: pitch straight to 12 at 48 then to 24 at 63, cutoff 2.94 octaves x (0.596 u + 0.404 u^2), amp 1.955 x that pitch curve / 24, pan 1.183 u + 0.801 u^2, Ctrl 1 0.596 u + 0.404 u^2. Amp is gain = (1 + amount x source)^2, bracket 0..2. Sources: an LFO or a held EG is 1.0; velocity is 0..1 for pitch / pan / Ctrl 1 but zero at 80 and +1 at 127 for cutoff and amp; keyboard is one unit per octave from C4 on pitch routes (a quarter of that on cutoff); LFO2's square is 0..+1. FILTER EG INT is 7.98 octaves at +-63, linear, and follows E (not its square: checked at five sustain levels); KEY TRACK is track / 48 octaves per octave up to 48 then on to 1.5 at 63, pivot C4 (measured). ⚠ A first pass applied the velocity family's curves to every source and made the bank WORSE (tone median 4.2 -> 5.1): LFO -> cutoff then moved 1.6 octaves instead of 7.8. The original u^2.4 had been close to the EG / LFO family for cutoff.
- LEVELS AND DISTORTION, measured on the VST: a full-level sine is the unit (1.0). Waves: saw +-1 (Osc 1's carries 0.173 extra fundamental, Osc 2's does not), square +-0.667, triangle +-1.333 (the plug-in matches loudness, not peak), mixer noise 1.6 rms at full. The Osc 1 / Osc 2 / Noise level knobs follow `level_curve` (0.404 at 64), the Amp level knob is a square (0.254 at 64); both decoders now keep the three knobs (`osc1_level`, `osc2_level`, `amp_level` in TimbreParams, (raw + 1) / 128 with 0 = not recorded: the built-in presets.h has zeros and falls back to mix x level), because `osc_mix` + `level` folded them together and lost how hard the mixer drives the filter and the distortion. The engine plays `timbre_extra.lvl_osc1 / lvl_osc2 / lvl_amp` (slot state: extras 31-33); the page's Osc Mix and Level knobs are folded back into them when turned. DISTORTION is a gain of 2.69 into a hard clip at 1.55 (it was a tanh that was also applied, mildly, with distortion off); where it sits and what feeds it: see DISTORTION PATH below.

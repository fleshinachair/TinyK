# TinyK - microKORG Synth Module for Ableton Move (Schwung Framework)

## Project Overview
- A 4-voice polyphonic / 2-voice dual-timbre virtual analog synth engine running on Ableton Move via the Schwung runtime.
- DSP core is C: `src/dsp/dsp.c` (engine), `src/dsp/dsp.h`, `src/dsp/syx_bank.h` (runtime .syx loader, included by dsp.c), `src/dsp/arp.c` / `arp.h` (arpeggiator; dsp.c includes arp.c once, so every build and tool still compiles dsp.c alone), `src/dsp/presets.h` (built-in bank, generated). `src/dsp.c` / `src/dsp.h` are one-line include shims.
- UI: `src/ui.js`. Manifest: `src/module.json`. The engine also serves its own `ui_hierarchy` JSON (`MK_UI_HIERARCHY` in dsp.c): keep the two in step.

## Build, Install & Test
- `./scripts/build.sh` cross-compiles `build/dsp.so` (ARM64, Cortex-A72) and packages `dist/tinyk/` + `TinyK.tar.gz` (holding `tinyk/`). Toolchain order: Docker (scripts/Dockerfile, only if `docker` is on PATH) -> CMake when `$CROSS_PREFIX` is set -> `aarch64-linux-gnu-gcc` -> Zig. This Windows machine has neither Docker nor a GNU cross-gcc, so the build always takes the Zig path with the bundled `.toolchain/zig-windows-x86_64-0.13.0/zig.exe` (gitignored; a `zig` on PATH also works):
  `zig cc -target aarch64-linux-gnu.2.35 -mcpu=cortex_a72 -O3 -fPIC -shared -Wall -Wextra -Isrc -Isrc/dsp src/dsp/dsp.c -lm -o build/dsp.so`
  (glibc 2.35 target, matching the Move; the result must be warning-free). The host-side tools build the same sources natively with the same zig.exe (`zig cc` without `-target`), see Verification tools.
- Package contents: dsp.so, module.json, ui.js, presets.json, help.json, presets.h, release.json and an EMPTY `banks/` (README.txt only): a release never redistributes .syx banks, and `./scripts/install.sh` copies none unless `INSTALL_BANKS=1`.
- `./scripts/install.sh` copies the module to the Move over SSH: default `ableton@move.local` (key-based login), override with `MOVE_HOST=ableton@<ip>`. Destination `/data/UserData/schwung/modules/sound_generators/tinyk`; an old upper-case `TinyK/` there is migrated (its banks copied over, then removed); dsp.so is swapped via `dsp.so.new`; banks already on the Move are kept, and local `banks/*.syx` are copied only with `INSTALL_BANKS=1` (never TinyK_Default.syx, the built-in bank's source). Reload the slot (or restart Schwung) afterwards.
- Module id `tinyk` = directory name, lowercase: Schwung requires `^[a-z0-9][a-z0-9-]*$`, the shadow UI lowercases ids into the Set's slot files, and the chain host loads `sound_generators/<id>/dsp.so` from them on boot (ext4, case-sensitive). The old id "TinyK" saved slots as "tinyk" that never restored. Display name stays "TinyK".
- Slot persistence: Schwung autosaves `get_param("state")` into `set_state/<set>/slot_N.json` every ~5 s and hands it back via `set_param("state")` on boot / Set change (the C chain parser reads `synth.config.state`). A failed read (TinyK used to return -1 for "state") makes it keep the stale file forever. TinyK's state (`build_state_json` / `apply_state`): `tinyk_state` version, bank by name, preset, params, both timbres' params and extras, voice mode, timbre edit/balance, octave, delay time base.
- Release: bump `version` in `src/module.json` and `release.json` together. `release.json` stays 0.9.0 until the user launches (their call; module.json says 1.0.0). `release.json` (repo root, Schwung catalog format `{version, download_url}`) points at the GitHub release asset `https://github.com/fleshinachair/TinyK/releases/download/v<version>/TinyK.tar.gz`; the catalog entry needs `github_repo` fleshinachair/TinyK and `asset_name` TinyK.tar.gz.
- Shell scripts must stay LF and executable (`.gitattributes`, git mode 100755).
- Default bank: `python tools/make_default_bank.py` reads banks/MicroKorgFactory.syx and writes banks/TinyK_Default.syx: 128 original names (`NAMES`, 12 characters max) and a seeded jitter of 1-2 steps on 1-3 continuous values per active timbre (cutoff, EG attack / decay / release, Osc 2 tune; EG 0 / top, unison tune, selectors and vocoder programs untouched). It is a derivative of Korg's factory programs, not an original sound set.
- Preset generator: `python tools/extracts_presets.py [banks/TinyK_Default.syx]` writes presets.h (4 copies) and presets.json (2 copies). The committed presets.h comes from TinyK_Default.syx and is the compiled-in default bank ("Built-in"); the .syx files are gitignored and never shipped. `FACTORY_LABELS` is only the fallback for dumps without names.

## Architecture Rules & Guidelines
1. **SysEx Parsing:**
   - Always open and write files using explicit UTF-8 (`encoding="utf-8"`) to prevent Windows `cp1252` encoding errors.
   - Values extracted into `presets.json` and `presets.h` must normalize strictly between `0.0f` and `1.0f`.
   - Never overwrite valid patch data with placeholder or copy-pasted floats.
   - `tools/extracts_presets.py` and `src/dsp/syx_bank.h` are the same decoder in two languages: change both together and run `tools/test_bank_loader.py`.

2. **DSP & Voice Architecture:**
   - Cutoff, key tracking, filter EG and virtual patches are summed in control pitch (octaves), converted to Hz once: `fc = cutoff_base_hz * 2^(knob * cutoff_octaves + keytrack + EG + patches)`.
   - Filter Envelope Intensity (`env_int`) is bipolar (`0.5` = neutral, `<0.5` = negative modulation, `>0.5` = positive modulation).
   - In Layer mode (`voice_mode == 1`), the engine allocates two voices: Timbre 1 (Voice A, panned left) and Timbre 2 (Voice B, panned right), mixed by `timbre_balance`.
   - The voice mix is soft-clipped (`tanh`) so stacked voices / both timbres cannot clip digitally.
   - Real-time path: no heap allocation, no file I/O. Renders must be deterministic (the noise generator is reseeded in `synth_init`).

3. **Filter (svf_process_2pole):**
   - Zero-delay-feedback (TPT) SVF with the correct solution `hp = (x - (k + g) * s1 - s2) / (1 + g (g + k))`. The old `k * s1` (missing g) plus tanh on s1/u and +-2 state clamps went unstable near the cutoff ceiling and sprayed kHz of hiss (a 131 Hz saw through LPF12 res 0.35 at 12.9 kHz had an 8 kHz centroid). The loop is linear (stable for any k > 0); the filter input has a soft clip (`tanh`, gain 1 + 0.5 res) and nothing else; states have a wide safety clamp (`SVF_STATE_LIMIT` 64).
   - BPF12 is the SVF's band output; Q = 1/k exactly (checked numerically). Its centre has its own knob curve, `bpf_cutoff_octaves` 10.36 and `bpf_cutoff_offset` +0.56 octave (+0.50 / +0.43 / +0.37 octave over the LPF mapping at cutoff 32 / 64 / 96), and `bpf_k0` 2.13 (Q 2.12 at res 63): fitted on the VST takes `ref_bpf12_res63_cut{32,64,96}_c3.wav` (saw, Osc 2 / drive / EG int / key track off), harmonic rms 5.61 -> 3.37 dB. Only res 63 was measured: Q at other resonances scales with bpf_k0 (res 0 now 0.47).
   - Distortion (`drive`, timbre byte 27 = 0.5 when on) is in the amp section, after the filter: `dist_ceiling * tanh((1 + drive * drive_gain) * x / dist_ceiling)`, drive_gain 2.0, dist_ceiling 2.0. On the VST it is mostly level (+19 dB on B.11, spectrum nearly unchanged); the engine runs ~17 dB hotter relative to its clip points, so it gets +4.8 dB with B.11's shape intact (2.6 vs 2.5 dB rms clean). More gain buys level with buzz.
   - Damping: LPF24 stages start Butterworth (k0 = sqrt 2, measured on the VST), LPF12/HPF k0 = 2, both `k = k0 * (1 - 0.5 * res_damping_range * res)`. BPF: `k = bpf_k0 * 2^(-4.38 res)` (exponent from the earlier res 0 / 63 measurement; bpf_k0 fitted at res 63).
   - Cutoff ceiling `cutoff_ceil_hz` = 19 kHz; the SVF clamps fc to 0.45 fs internally.
   - Key tracking: `(note - KEYTRACK_PIVOT) * (2 * keytrack - 1) * KEYTRACK_SLOPE / 12` octaves (keytrack 0..1, 0.5 = off), pivot 60, slope 1.0. (The VST measured ~2.0 about ~62 at +63, but that made the +48 presets worse; kept 1:1 until intermediate values are measured.)

4. **Brightness tilt:** the audible noise (noise level and Osc 1 Noise) is pre-shaped by the inverse of a lower shelf, `noise_tilt_db` 18 dB (same corner), so it keeps part of the tilt's top. HPF12 has its own cutoff ceiling, `hpf_ceil_hz` 15 kHz (knob plus modulation; LPF / BPF keep `cutoff_ceil_hz` 19 kHz). Both were fitted together on A.21's off-beat hat (`ref_a21_timbre2_drum_c3.wav`, where LFO2 -> cutoff pins the HPF at its ceiling): at the shared 19 kHz ceiling nearly all the hat sat at 15-20 kHz (5-15 kHz content 34.4 dB under the kick vs 26.6 on the VST), so it read as quiet although its RMS matched; now 23.5 dB, the band profile within 3.1 dB rms (13.7 before), the hat 9.0 dB under the kick (VST 8.7). The calibration total moved 111.75 -> 111.84 (A28, the noise patch, 13.62 -> 13.71). S&H keeps the raw noise. The tilt itself is a first-order high shelf on the voice mix, after the filters and before the soft clip (`tilt_db` 26.7 dB, `tilt_hz` 20 kHz): ~+2 dB at 3 kHz, +7 at 8 kHz, +18 at 17 kHz. It matches the VST's open saw (co_127) within 1.6 dB rms. Post-filter is deliberate: it is linear there and leaves the pre-filter drive alone; a per-voice pre-filter tilt scored worse (106.8 vs 104.1).

5. **Virtual patch & LFOs:** per timbre, 2 LFOs (LFO1 saw/square/triangle/S&H, LFO2 saw/square/sine/S&H; tempo sync at the session tempo (`host_tempo_bpm()`: the Set tempo from Schwung's public move-info (`schwung_move_info()`, found by dlsym at init, audio-thread safe; `move_info_t` in dsp.h mirrors src/host/move_info.h, offsets checked by _Static_assert), unless Move follows external MIDI clock or move-info is invalid; then `get_bpm`, else `lfo_tempo_bpm` 120. move-info's tempo follows the tempo knob while stopped (polled on the Move 2026-10-07: 103 -> 120 BPM with the transport stopped); get_bpm is the measured MIDI clock while PLAY runs and only holds the last measured tempo when stopped. Smoothed: the Set tempo over ~50 ms, a get_bpm within ~50 ms for changes > 2 BPM and over ~1 s for the +-0.3 BPM clock jitter), and while the transport runs (`get_beat_position` >= 0) free-running synced LFOs lock their phase to the beat (cycle start on beat 0; not an LFO2 whose rate a patch modulates); key sync restarts at the positive peak; the saw FALLS +1 -> -1: 37 of 39 saw -> amp routes in the factory / MS2000 banks are positive, rhythmic gates like A.21 AutoHouse that a rising saw played backwards) and 4 patch slots (sources 0-7: EG1 (filter), EG2 (amp), LFO1, LFO2, velocity, keyboard, Pitch Bend (-1..+1), Mod Wheel (CC1, 0..+1; CC2 drives nothing); destinations pitch, osc2 pitch, osc1 ctrl1, noise, cutoff, amp, pan, LFO2 rate). Depth = full scale * (|int|/63)^`patch_int_curve` (2.4 measured); full scale 24 semitones (pitch, measured) and 10.61 octaves (cutoff, lower bound). Amp routes are not summed: each is a gain stage `max(0, 1 + amt * src)`, the product is squared and capped at full level (1 / timbre level), fitted on the A.21 hat (3.9 dB rms over its envelope vs 11.5 for the sum, which went silent at 2/3 of the cycle; silence exactly at the cycle end and a level kick half, as on the VST). Pan has its own `patch_pan_curve` 0.6 (chosen, not measured: +-7.6 dB swing at +20, hard L/R at +63; 2.4 gave +-0.7 dB). Bend and wheel sources are 0 until a message arrives, so a wheel at rest adds nothing. Patch LFO outputs are slew-limited (`LFO_SLEW_S` 1.5 ms per full swing) then one-pole smoothed (`LFO_SMOOTH_S` 0.5 ms): saw wraps, square edges, S&H steps and key-sync restarts no longer click (A.21's gate, A.31's S&H -> pan +63, checked in test_behavior).

6. **Arpeggiator (`src/dsp/arp.c`):** each program's own (program bytes 14-15, 32-36, see SysEx notes), decoded into `struct ArpParams` (`ARP_FIELDS`), loaded with the program (on/off as stored; the Arp knob `arp_on` on Perf overrides it until the next program; the Arp Settings and Arp Steps pages edit the rest and the step pattern; all are saved in the slot state). MIDI keys go through it (`key_note_on` / `key_note_off`); `synth_note_on` / `synth_note_off` stay direct, so single-note renders, calibration and the audit are unaffected. Types UP, DOWN, ALT1 (ends once), ALT2 (ends twice), RANDOM (deterministic xorshift), TRIGGER (all held keys together, the octave rising per step); range 1-4 octaves; resolution 1/24 .. 1/4; gate x step (100 % = to the next step, minimum 2 %); swing moves every second step by swing/3 of a step; the trigger pattern rests steps whose bit is SET (inferred: 17 of the factory's 23 arp programs store 0); the note order advances on played steps only; latch keeps the keys until the next key after a release. Clock: the transport's beat grid while it runs and key sync is off, else free-running from the first key at the session tempo; `synth_render` renders in segments ending at arp events, so steps start on the sample (one segment per block when the arp is off). Layer mode: the arp plays its target timbre (both, T1 or T2) and the other timbre plays the keys (A.21: T1 bass arpeggiated, T2 drum held). Arp notes restart the target timbre's key-synced LFOs. The program's own arp tempo (bytes 30-31) is ignored for the session tempo. Checked in test_behavior (`test_arp`) and test_bank_loader.

## Presets, banks and selection
- Built-in bank: `FACTORY_PRESETS` in presets.h (used when there are no banks).
- Runtime banks (`syx_bank.h`): `v2_create_instance` scans `<module_dir>/banks/*.syx` once, decodes up to 16 banks (alphabetical, case-insensitive) into static storage (~54 KB each). Accepted: microKORG `F0 42 3g 58` or microKORG S `F0 42 3g 00 01 40`, function `4C` (ALL PROGRAM DATA, 128 programs, 37163 bytes) or `50` (ALL DATA). Anything else (single-program `40` dumps, truncated/oversized/random files) is skipped; with several SysEx messages in a file the first valid bank is used. Selecting a bank later is a pointer swap (`active_presets()`), never file I/O.
- Labels: the stored 12-character name when present ("A.11 Trancey" style names keep their code; plain names get it prepended), else the code ("A.11").

## Controls & UI (Schwung host)
- The host builds the screens from `ui_hierarchy` (src/module.json, also served by the engine as MK_UI_HIERARCHY, generated from it and checked identical by test_bank_loader.py) plus the engine's live `get_param("chain_params")`, which overrides inline metadata. Enums display their option names and travel as indices; set_param also accepts option names. Host code for reference: shadow/ and shared/param_pages/ under /data/UserData/schwung on the Move.
- Root level: only the preset browser (`list_param` preset, `count_param` preset_count, `name_param` preset_name; no knobs): the header shows the live patch name and the jog wheel steps all 128 programs. Its nav entries are the knob pages, each its own level (the host names a page after its level and re-anchors a renamed page by level): **Perf** (`perf`: Category, Program, Cutoff, Resonance, Amp Atk, Amp Rel, Arp, Mod Wheel), **Osc/Timbre** (`osc`: Wave 1, Pulse Width, Wave 2, Semi, Tune, Voice Mode, Timbre Edit, Timbre Bal), **Envelopes** (`env`: Filter Atk/Dcy/Sus/Rel, Amp Dcy/Sus, Key Track, EG Int), **Effects** (`fx`: Chorus Mix, Delay Time/Fdbk/Mix, LFO1/LFO2 Rate, Master Vol, Pan), **Mix/Filter** (`mix`: Osc Mix, Noise, Sync/Ring, Filter Type, Portamento, Level, Drive), then Bank, then **Arp Settings** (`arpset`: `arp_type` UP/DOWN/ALT1/ALT2/RANDOM/TRIGGER, `arp_range` 1-4 Oct, `arp_resolution` 1/24..1/4, `arp_gate` 0..100 %, `arp_swing` -100..100 %, `arp_latch`, `arp_key_sync`, `arp_target` Both/Timbre 1/Timbre 2; one table, `ARP_PARAMS` in dsp.c, serves set/get, chain_params and the slot state; a turn changes the running arpeggio at once: resolution / swing re-find the next step, latch off drops keys no longer held, a target change moves the arp and the held keys to their new timbres), then **Arp Steps** (`steps`: `arp_step1`..`arp_step8`, enum Rest / Play = the program's trigger pattern, live; a step past the pattern's length extends it; pattern and length are saved in the slot state). Category = `category`, enum of 8 (Trance, Techno/House, Electronica, DnB/Breaks, Hiphop/Vintage, Retro, SE/Hit, Vocoder = matrix rows 1-8); Program = `patch`, 16 positions A1..A8, B1..B8 = both bank sides of that row. Preset index = (patch / 8) * 64 + category * 8 + patch % 8. There is no standalone A/B knob: Program 1-16 covers both sides. Not on any page: detune (replaced by Semi/Tune), sub_level (the microKORG has none), mod_int, vel_sens.
- Live labels (chain_params and the served ui_hierarchy follow the engine state): Program's options are the category's patch names in the active bank ("B.12 ARPEJMATR", shown on touch/turn) with `short_options` A1..B8 for the cell square (module.json keeps the static A1..B8). The per-timbre pages are named "... [T1]" in module.json; the engine serves "[T2]" while Timbre 2 is edited (Layer mode + Timbre Edit 2, `edit_timbre()`), and then gives the per-timbre controls `label` "T2 <label>" and `short_name` "T2.CUT" etc. (`T2_LABELS`, fitted to the host's 5-character cell). The host re-reads both on a preset jog or list pick but not on a knob turn, so after a Category/Bank/Timbre Edit/Voice Mode change `is_loading` answers "1" once (`g_labels_reported`) and the host re-reads on its 1 -> 0 edge.
- Host-facing value formats: selector params (`SELECTORS` in dsp.c: wave1, wave2, sync_ring, filter_type) are enums over the 0..1 engine value, with `short_options` for the option square (<= 4-5 narrow characters fit one line; longer folds, "Single" -> SIN/GLE, so Voice Mode / Timbre Edit carry SNGL/LAYR, T1/T2). Filter Type: LPF24, LPF12, BPF12, HPF12. Sync / Ring is in the hardware order Off, Ring, Sync, Ring Sync (OFF, RING, SYNC, R.SNC), remapped to the engine's off, sync, ring, both (`SYNC_RING_TO_ENGINE`, as in syx_bank.h). wave1/wave2 are enums (Saw, Square, Triangle, Sine, Vox, DWGS, Noise / Saw, Square, Triangle; short SAW, SQR, ...), so the host draws its waveform icon (Vox and DWGS fall back to its sine). They travel as indices; set_param also takes names, and a value with a decimal point as the normalized 0..1. `osc2_semi` (-24..24) and `osc2_tune` (-50..50 cents) are ints that read and write `detune` (clamped to its +-24 st). `level` and `noise_level` are the edited timbre's `timbre_extra` level / noise level. `mod_wheel` (int 0..127, cell "MOD") stands in for the wheel the Move lacks: it sets the Mod Wheel patch source (`modwheel_src`) like CC1 does, last mover wins, and reads back CC1 too. No EQ yet (not decoded, no DSP).
- Bank page (`bank` level, entered from the root's "Bank" entry): the **Bank** knob (`bank_file`) whose enum options are "Built-in" plus the .syx file names found at start-up (from the live chain_params, JSON-escaped); `bank_file_name` returns the active name, `bank_file_count` the number of choices. "Browse banks" opens `bank_list`, an items level (`items_param` bank_list returning `[{"index","label"}]`, `select_param` bank_file, back to root). Changing bank keeps the program.
- src/ui.js mirrors this for the module's own screen: PERF, OSC / TIMBRE, ENVELOPES, EFFECTS, MIX / FILTER and BANK pages; per-timbre pages show [T1]/[T2] in the header and T2.xxx labels while Timbre 2 is edited; Program shows the patch name.
- Legacy keys still accepted: `bank_side`, `program` (11..88), `genre_category`, `program_num` (1..16), `preset` (0..127; integer strings are indices). Other getters: `bank_file_name:<n>`, `preset_name:<idx>`.

## SysEx Format Notes (verified)
- 128 programs x 254 bytes after 7-to-8 unpacking. Timbre 1 at byte 38, Timbre 2 at 146.
- Voice mode is byte 16 bits 4-5 (0 = Single, 2 = Layer, 3 = Vocoder). Byte 14 is NOT the voice mode.
- Timbre offsets: 7 osc1 wave, 8 / 9 osc1 Control 1 / 2 (`osc1_ctrl1` / `osc1_ctrl2`, raw / 127; `pulse_width` repeats Ctrl 1 for the Pulse wave; for Sine, cross-mod depth / LFO1 modulation of it), 12 osc2 wave/mod select, 13/14 osc2 semitone/tune, 16/17/18 osc1/osc2/noise level, 19 filter type, 20 cutoff, 21 resonance, 22 EG1 int, 24 key track, 25 amp level, 27 bit 0 distortion, 30-33 EG1 (filter) ADSR, 34-37 EG2 (amp) ADSR (checked: swapping or ADRS order scores far worse), 38-40 LFO1 (wave/key sync, rate, tempo sync), 41-43 LFO2, 44-51 four patches as (route: bits 0-3 source, 4-7 destination; intensity 64 = 0).
- Hardware backup dumps can have blank names (bytes 0-11); VST exports (e.g. banks/MicroKorgFactory.syx) carry real names. test_bank_loader.py blanks them for its scan / label checks.
- `wave1` is index/6 over Saw, Pulse, Tri, Sine, Vox, DWGS, Noise. Vox/DWGS are additive approximations, not the sampled waves.
- Arpeggiator (program bytes, checked against the factory banks; NOT timbre +41..45, which are LFO2 and the patches): 14 trigger length - 1, 15 trigger pattern (bit n = step n + 1, set = rest), 30-31 arp tempo, 32 bit 7 on / bit 6 latch / bits 4-5 target (both, T1, T2) / bit 0 key sync, 33 bits 0-3 type / bits 4-7 range - 1, 34 gate %, 35 resolution 0..5, 36 swing (signed %).
- Program byte 19 is the delay tempo sync: bit 7 on, bits 0-3 the time base, 1/32 .. 1/1 (`DELAY_SYNC_NOTES`, the reverse of the LFO note order: the factory's common 7 / 5 / 8 are then 3/16, 1/8, 1/4). Decoded as fx `delay_sync` ((index + 1) / 15, 0 = free) by both decoders; a synced program's Delay Time knob steps the time base at the session tempo (`delay_sync_note`). The delay buffer is 2 s; free delay times stay 0..1 s.
- Host API: Schwung's move-info (`schwung_move_info`, see Virtual patch & LFOs) is the live Set tempo; `host_api_v1_t` in dsp.h mirrors Schwung's src/host/plugin_api_v1.h field for field (get_bpm at +88, get_beat_position at +112, checked by _Static_assert); every callback is NULL-guarded. Never append fields to it.
- Vocoder programs get a generic carrier (`data_valid: false`). The delay has no on/off bit: depth 0 = off, otherwise a send on the unity dry signal. The VST's Mod FX / Delay are likewise off only at depth 0.

## Verification tools
- `python tools/audit_all_presets.py`: renders all 128 built-in presets, flags SILENT / VERY QUIET / CLICK ONLY / UNSTABLE.
- `tools/test_behavior.c`: Layer triggering, timbre-edit routing, envelope time curves (build: `zig cc -O2 -Isrc/dsp tools/test_behavior.c src/dsp/dsp.c -lm`).
- `python tools/test_bank_loader.py`: C loader vs presets.h parity, scanning/skipping, names, selection, every bank in `banks/` cross-checked against extracts_presets.py, and the host API (v2 create/set/get: chain_params, bank_list, Category/Program, ui_hierarchy == module.json).
- `python tools/fit_filter_sweep.py [--selftest]`: fits cutoff curve / EG scale from VST sweeps (`--cut KNOB=FILE`, `--eg INT=FILE`, `--stage-q`); `--selftest` must recover the engine's own constants.
- Tempo diagnostics: build with `-DTINYK_TEMPO_LOG` (never shipped: host->log does blocking file I/O) and `touch /data/UserData/schwung/debug_log_on` on the Move; TinyK logs get_bpm / move-info tempo / beat position / clock status to debug.log at start and on changes. Remove the flag afterwards (it slows every module's logging). BusyBox `head` needs `-n`.
- `python tools/render_demo_sweeps.py [--all]`: demo WAVs with a cutoff sweep (`output/demos/`), or 4 s auditions of all 128 built-in presets (`output/all_presets/`). `output/` is gitignored.

## Calibration (tools/calibrate_dsp.py)
- `python tools/calibrate_dsp.py check-syx | baseline | identify | tune [--exclude KEY] [--no-freeze] [--apply]`. Engine constants live in `tinyk_tuning_t` / `TINYK_TUNING_DEFAULTS` (compile-time in the shipped build, adjustable with -DTINYK_TUNING via the ctypes library built from tools/test_render.c).
- References: `tools/reference/ref_<KEY>_C3.wav` with the program in `mk_<key>.syx` (A11, A12, A14, A28, B11; A21 dropped: its take is a drum click). Also `ref_bpf12_res63_cut{32,64,96}_c3.wav` (BPF calibration) and `ref_b11_no_osc2_c3.wav` / `ref_b11_no_dist_c3.wav`. B.11's LFO2 (-> cutoff +29, +-1.65 octave) is free running and each VST take catches it at a different phase (no_osc2 near the trough, the original take mid-sweep rising, no_dist near the peak), so B.11 takes only compare with the LFO pinned (route off, fitted cutoff offset): no_osc2 then matches to 2.5 dB. no_dist shows a harmonic comb no Osc 2 pitch reproduces (7.4-8 dB): unexplained.
